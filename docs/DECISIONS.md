# Decisions

Deviations from `docs/SPEC.md` and notable judgment calls, one or two lines each.

- The original SPEC.md was not in the repo; the orchestrator wrote `docs/SPEC.md` from the task brief, adding the hoca-ozet / ogrenci-ozet / bana-ozet features as M4.
- Docker is not available on the dev machine: GreenMail runs locally as the standalone jar; CI uses the Docker image.
- mcp 2.3's high-level server is `mcp.server.mcpserver.MCPServer` (FastMCP was renamed); `ToolAnnotations` from `mcp.types`.
- The SDK calls `logging.basicConfig`; we install a stderr-only root handler first so that call is a no-op and nothing can reach stdout.
- Logged secrets are scrubbed by a redaction filter (`logs.register_secret`), including tracebacks.
- `config.toml` is strict (`extra="forbid"`); any key containing `password` is rejected without echoing its value.
- `POSTA_ALLOW_SEND=0` explicitly overrides `sending.enabled=true` in the file.
- Tool modules expose `register(server, deps)`; `Deps.mailbox()` returns a context-managed `posta_mcp.imap.Mailbox(config)`.
- Ruff rules pinned (`E4,E7,E9,F,I,B,UP`) and `.claude/` (agent worktrees) excluded so lint is stable across ruff versions.
- GreenMail 2.1.14 standalone jar (Java 8+ bytecode, pinned SHA-256) locally; `greenmail/standalone:2.1.14` image in CI. Test certs are generated by `scripts/greenmail.py certs` and never committed.
- GreenMail has no STARTTLS and no SPECIAL-USE: `starttls` is covered by unit tests with a mocked server, and special folders fall back to configured names in integration tests.
- CI actions are pinned by commit SHA; CI installs with `uv sync --locked` and checks `ruff format`.
- Send confirmation uses the SDK resolver/`Resolve` elicitation pattern because plain `ctx.elicit()` raises `NoBackChannelError` on the 2026-07-28 protocol that Claude Code uses.
- Boğaziçi presets: login = local part, separate student/staff host variants by email domain (research: university-hosted, plain IMAP auth, no OAuth). All unverified.
- `iso-8859-9`/`latin5` are decoded as windows-1254 (a strict superset, as browsers do). Mail labelled latin-1/ascii/cp1252 but containing ý/ð/þ/Ý/Ð/Þ is decoded as windows-1254 (common Turkish mislabel); genuine Latin-1 with those letters is misread.
- Zero-width, bidi-override and Unicode tag characters are stripped from decoded text (ASCII-smuggling defence). HTML hidden via display:none, visibility:hidden, font-size:0, opacity:0, mso-hide, off-screen positioning or `hidden` is dropped; white-on-white is not (legitimate mail uses it).
- Untrusted content is wrapped with a per-call random nonce in both delimiters; header fields (from, subject) are inside the wrapper too.
- SMTP must send `send_bytes(msg)` (no Bcc header) to `envelope_recipients(msg)`; drafts keep Bcc via `message_bytes(msg)`.
- Reply attribution line is English; `Ynt:` folds like `Re:`. Non-ASCII local parts are rejected; IDN domains go out as punycode.
- Presets support `[[variants]]` chosen by exact email domain (Boğaziçi: `student`, `staff`). `pt.`/`retired.` accounts use different hosts and must set them explicitly for now.
- Tools are plain sync functions; the SDK already runs sync tools in a worker thread.
